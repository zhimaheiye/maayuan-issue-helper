# 日志定位与判断边界

以下来自桌面发行目录的实际结构。不同版本可能调整路径，缺失时报告缺失，不能杜撰文件。Android 版不在采集脚本当前支持范围内。

| 来源 | 常见位置 | 用途 |
|---|---|---|
| GUI / MFAAvalonia | `logs/log-YYYYMMDD.log` | 启动、版本、资源加载、连接、界面异常 |
| MaaFramework | `debug/maa.log`、`debug/maa.bak.log` | 任务入口、节点识别、动作、超时、任务结束 |
| Python Agent | `debug/custom/YYYY-MM-DD.log` | Agent 启动、依赖、Python 异常、自定义动作 |
| 错误截图 | `debug/on_error/` | 失败时画面；本版脚本不采集 |
| 资源版本 | `interface.json` 顶层 `version` | 当前磁盘资源版本，不等于 GUI 或框架版本 |

不默认收集 `config/`、`appsettings.json`、账号数据、CDK、完整环境变量或 `temp/`。只有定位确实需要时，提取用户授权且相关的少量配置项，经过复核后写入报告，不复制原配置。自定义 observer、额外诊断目录不是每个官方版本都有，不当成通用必需项。

日志中常见 `task_id`、`entry`、`node_id`、`cur_node_` 有助于关联。`Node.Recognition.Failed` 可能只是多个候选之一未匹配；需要看 next 列表、后继节点、Task.Failed/停止原因及时间线。卡住时日志可能没有 ERROR；循环节点、重复识别及最后一次有效动作也有价值。

框架日志轮转后 `maa.bak.log` 可能包含启动和前半段；不能只看 `maa.log`。GUI 能运行并不证明 Agent 已成功启动。较早的无关 GUI 错误未必解释后续任务卡点。

不要把终端显示乱码当作源文件损坏。脚本支持 UTF-8、带 BOM 的 UTF-16 和 GB18030；无法可靠解码的文件会被排除并记录，绝不用替换字符悄悄糊过去。文件修改时间用于挑选候选，不代表事件发生时间。日志无时区时明确“日志本地时间，时区待确认”。

采集有上限：默认每文件输出 4 MiB、总输出 24 MiB、单文件最多读取 64 MiB。超出会记录截断；命中日期在截断位置之后可能丢失。遇到这种情况，明确缺口，按需要提高上限重新采集到新目录，或由 AI 提取目标时间窗口；不要称“完整日志”。
