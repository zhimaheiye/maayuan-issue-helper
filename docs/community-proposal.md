# 社区提议草稿

我在使用 MaaYuan 和尝试排查一些问题时，发现只靠运行截图和简短描述，有时很难判断问题发生在哪一步，也容易漏掉相关日志。因此整理了一个“故障反馈助手”技能，供有需要的使用者试用。

它可以配合支持本地文件操作的 AI Agent，收集并分析 MaaYuan 日志，生成一份适合直接发到频道的文字说明，以及供进一步排查的详细报告和日志包。不会使用 GitHub 也可以使用；频道不方便上传附件时，可以先发布文字说明，日志包自行保留，再按频道现有规则补充材料。

建议使用前先复制一份完整的 MaaYuan 文件夹，保留原目录，让 AI 在副本中分析。如果进一步让 AI 尝试修复，也请在副本中操作并保留修改记录。本地修改可能被后续更新覆盖，或与新版不兼容；本地修复成功不代表官方版本已经修复。

这个工具由我作为项目使用者和社区参与者整理，主要用于提高反馈材料的清晰度，不代表开发团队。反馈仍沿用现有渠道；AI 的判断也需要结合日志进一步核实。发布前请检查报告及日志中的个人信息。

项目地址：https://github.com/zhimaheiye/maayuan-issue-helper

# 推进方式建议

先作为可选工具小范围试用，不作为社区反馈门槛。可以请愿意尝试的使用者提供使用体验；若与维护者沟通，重点询问现有反馈中通常缺少什么日志、报告格式是否便于阅读，避免替其设计接单流程。

评价试用结果时关注：能否找到正确时段的日志、是否减少补问、是否把推测写成结论、是否遗漏隐私、安装是否容易。不以解决了多少 Bug 或响应速度作为工具承诺。

QQ 频道的具体附件能力与权限未实测，因此以“可复制的正文”为默认交付；网盘和 GitHub 附件均为可选补充。GitHub 仓库、网盘分发、技能市场上架是不同渠道，不需要为了试用同时完成全部渠道建设。
